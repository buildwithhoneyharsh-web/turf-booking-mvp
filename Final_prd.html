Product Requirements Document (PRD): Turf Booking Platform (Ratlam MVP)

Core Strategy: Eliminate double-bookings and digitize turf management in Ratlam without forcing users through a clunky payment gateway. 1-Tap Booking, Single-Source-of-Truth Slot Matrix, Double-Booking Elimination.

1. Pain Point vs. Platform Solution Matrix

# Turf Owner Pain Point Platform Technical Solution
1 Double-Booking Nightmare: Taking bookings across phone calls, WhatsApp, and walk-ins simultaneously without a central database. Single Source of Truth Calendar: Real-time atomic database locking. When a slot is booked online or blocked manually by the owner, it instantly turns red everywhere via WebSockets.
2 Last-Minute No-Shows: Zero financial friction for users to cancel or simply not show up after phone bookings. 1-Tap OTP Lock + 1-Hour Pre-Game Auto-Reconfirmation: Users book instantly via Phone OTP. 1 hour before match time, an automated WhatsApp message asks them to tap "Confirm Attendance". If unconfirmed, the slot automatically re-opens. Repeat offenders get blacklisted.
3 Overtime Slot Conflicts: Team wants to extend time when the next slot is booked. 55-Min Game Rule & Extension Guard: 5-minute buffer per slot. Owner app blocks top-ups if the adjacent slot is already booked and alerts both teams via WhatsApp 10 minutes before time ends.
4 Idle Afternoon Inventory: High demand during evening lights, zero demand during daytime heat. Dynamic Off-Peak Pricing Rule Engine: Automated rule builder allowing owners to set lower daytime rates.

2. Module & Feature Breakdown

Module A: Player-Facing Application (Mobile Web / PWA)

The primary user experience is delivered via a Progressive Web App (PWA) to avoid friction with native app stores while maintaining a native feel.

  • PWA Capabilities & Constraints: Installable to the home screen, app-like navigation, and strict server-authoritative logic (cached data must never be used to confirm a booking).
  • Identity & Auth (Low Friction): Phone Number + OTP Login via Fast2SMS and Supabase. Persistent Guest Browsing allowed until "Proceed / Book Slot" is clicked.
  • Discovery & Search: Home Screen Turf Feed with cover photos, sport tags (e.g., Badminton, Pickleball, Turf Football), surface details, and hardcoded Ratlam city filter for V1.
  • Multi-Court & Multi-Slot Booking Engine (Zomato/District Flow):
    • Interactive hourly slot grid grouped by sport and time.
    • Drill-down view to select individual pitches/courts (e.g., Court 1, Court 2) with clear surface metadata (e.g., Outdoor | Synthetic | Standard).
    • Multi-Selection Support: Users can select multiple courts or multiple consecutive hours in a single transaction.
    • Frictionless "Pay at Venue" Checkout confirms all selected courts in under 10 seconds.

Module B: Turf Owner Dashboard (Web / Mobile)

  • Multi-Ground Management & Operations: Owners can add unlimited grounds/pitches with custom names, tags, and surface metadata. Visual Live Calendar allows toggling or side-by-side viewing of multiple grounds.
  • 1-Tap Manual Slot Block (For Walk-ins): Instantly lock out online double-booking for specific grounds.
  • Overtime & Extension Guard: "Extend by 30 Mins" button with a Conflict Guard that blocks extensions if the next slot on that specific ground is already reserved.
  • Dynamic Pricing Engine: Off-Peak Rule Setup (e.g., Mon–Fri, 11 AM – 4 PM = ₹500/hr).

Module C: Automated Notification Engine

  • WhatsApp Business API (Primary Channel): Instant confirmation ticket (includes breakdown of all courts/slots booked), 1-Hour Match reminder, and Overtime warning sent 10 minutes before slot end.
  • SMS Service: Strictly used for high-speed Phone Login OTPs.

Module D: Super Admin Dashboard (Platform Owners)

  • Turf & Vendor Management: Add new turfs, edit details, upload cover photos, and toggle status (Active, Suspended).
  • User & Risk Management: Global Blacklist Manager to view and restrict users who triggered a "No-Show" across all turfs on the platform.

4. Development Workflow & Operations (Zero-Cost DevOps Pipeline)

Security Imperative: Booking availability MUST be protected by database transactions. The PWA frontend cannot be trusted to verify slot availability. Furthermore, the Supabase service-role key must NEVER be exposed to browser code.
  • Local Development is Mandatory: Developers must use the Supabase CLI to run a local instance of the database and authentication services.
  • Git-Based Migrations: All database schema changes (tables, columns, relations) must be stored in Git and applied through Supabase migrations. Casual schema edits through the live Supabase dashboard are strictly prohibited.
  • 2-Tier Lean Deployment: Code is tested locally -> Pushed to GitHub main branch -> Vercel automatically deploys to Production connected to the single free Supabase PROD project.

5. Database Design & Data Model (Drizzle ORM)

The database relies on strict PostgreSQL constraints to serve as the single source of truth. The schema operates on a Turfs ➔ Grounds ➔ Slots hierarchy and utilizes a Parent-Child Booking Model (`bookings` ➔ `booking_items`) to enable multi-court and multi-hour checkouts seamlessly.

5.1 Booking & Double-Booking Strategy

  1. Represent each playable slot as a concrete row in the slots table linked to a specific ground_id (e.g., Court 1), generated for a 30-60 day rolling window.
  2. When a user selects 1 or more courts/slots and clicks Proceed, a PostgreSQL transaction claims all chosen slot rows utilizing SELECT ... FOR UPDATE.
  3. If all slots are available, a single parent record is created in bookings, and child records are inserted into booking_items linking to each slot_id.
  4. A UNIQUE(slot_id) constraint on booking_items serves as the ultimate safety guard ensuring no slot can ever be claimed by two active booking items.
  5. If even 1 selected court in a multi-court checkout fails validation, the entire transaction rolls back safely.
  6. Calculate and snapshot the price_snapshot on each item and sum into total_amount on the parent booking record.

5.2 Drizzle Schema Starter (MVP Core - Multi-Court & Parent-Child Enabled)

import {
  pgTable, uuid, varchar, timestamp, date, numeric, boolean, pgEnum, uniqueIndex, index
} from "drizzle-orm/pg-core";

export const userRole = pgEnum("user_role", ["PLAYER", "OWNER", "MANAGER", "ADMIN"]);
export const userStatus = pgEnum("user_status", ["ACTIVE", "SUSPENDED", "DELETED"]);
export const slotStatus = pgEnum("slot_status", ["AVAILABLE", "BOOKED", "BLOCKED", "MAINTENANCE"]);
export const bookingStatus = pgEnum("booking_status", ["CONFIRMED", "CANCELLED", "COMPLETED", "NO_SHOW", "EXPIRED"]);
export const bookingSource = pgEnum("booking_source", ["ONLINE", "PHONE", "WALK_IN", "OWNER"]);

export const users = pgTable("users", {
  id: uuid("id").primaryKey(), // Links directly to Supabase Auth UUID
  phone: varchar("phone", { length: 15 }).notNull().unique(),
  fullName: varchar("full_name", { length: 120 }),
  role: userRole("role").notNull().default("PLAYER"),
  status: userStatus("status").notNull().default("ACTIVE"),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
});

export const cities = pgTable("cities", {
  id: uuid("id").defaultRandom().primaryKey(),
  name: varchar("name", { length: 80 }).notNull().unique(),
  state: varchar("state", { length: 80 }).notNull(),
  timezone: varchar("timezone", { length: 50 }).notNull().default("Asia/Kolkata"),
});

export const turfs = pgTable("turfs", {
  id: uuid("id").defaultRandom().primaryKey(),
  cityId: uuid("city_id").notNull().references(() => cities.id),
  ownerId: uuid("owner_id").notNull().references(() => users.id),
  name: varchar("name", { length: 150 }).notNull(),
  address: varchar("address", { length: 500 }).notNull(),
  timezone: varchar("timezone", { length: 50 }).notNull().default("Asia/Kolkata"),
});

// Multi-Ground / Court Support Table
export const grounds = pgTable("grounds", {
  id: uuid("id").defaultRandom().primaryKey(),
  turfId: uuid("turf_id").notNull().references(() => turfs.id),
  name: varchar("name", { length: 80 }).notNull(), // e.g., "Court 1"
  code: varchar("code", { length: 20 }).notNull(), // e.g., "C1"
  surfaceType: varchar("surface_type", { length: 50 }), // e.g., "Synthetic", "Turf", "Wooden"
  environment: varchar("environment", { length: 20 }), // e.g., "Outdoor", "Indoor"
  isActive: boolean("is_active").notNull().default(true),
}, (t) => ({
  turfIdx: index("grounds_turf_idx").on(t.turfId),
}));

export const slots = pgTable("slots", {
  id: uuid("id").defaultRandom().primaryKey(),
  turfId: uuid("turf_id").notNull().references(() => turfs.id), 
  groundId: uuid("ground_id").notNull().references(() => grounds.id), // Links slot to specific pitch/court
  sportId: uuid("sport_id").notNull(), 
  slotDate: date("slot_date").notNull(),
  startAt: timestamp("start_at", { withTimezone: true }).notNull(),
  endAt: timestamp("end_at", { withTimezone: true }).notNull(),
  basePrice: numeric("base_price", { precision: 10, scale: 2 }).notNull(),
  finalPrice: numeric("final_price", { precision: 10, scale: 2 }).notNull(),
  status: slotStatus("status").notNull().default("AVAILABLE"),
}, (t) => ({
  slotIdentity: uniqueIndex("slots_ground_start_uidx").on(t.groundId, t.startAt),
  calendarIdx: index("slots_calendar_idx").on(t.turfId, t.slotDate, t.status),
}));

// Parent Booking Record
export const bookings = pgTable("bookings", {
  id: uuid("id").defaultRandom().primaryKey(),
  bookingCode: varchar("booking_code", { length: 20 }).notNull().unique(),
  turfId: uuid("turf_id").notNull().references(() => turfs.id),
  userId: uuid("user_id").references(() => users.id),
  customerName: varchar("customer_name", { length: 120 }).notNull(),
  customerPhone: varchar("customer_phone", { length: 15 }).notNull(),
  source: bookingSource("source").notNull(),
  totalAmount: numeric("total_amount", { precision: 10, scale: 2 }).notNull(), // Sum of all claimed slots
  status: bookingStatus("status").notNull().default("CONFIRMED"),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => ({
  phoneIdx: index("bookings_phone_idx").on(t.customerPhone),
  turfCreatedIdx: index("bookings_turf_created_idx").on(t.turfId, t.createdAt),
}));

// Child Booking Items (Allows selecting multiple courts/slots in 1 booking)
export const bookingItems = pgTable("booking_items", {
  id: uuid("id").defaultRandom().primaryKey(),
  bookingId: uuid("booking_id").notNull().references(() => bookings.id),
  slotId: uuid("slot_id").notNull().unique(), // Unique guard ensures slot cannot belong to 2 booking items
  priceSnapshot: numeric("price_snapshot", { precision: 10, scale: 2 }).notNull(),
});
